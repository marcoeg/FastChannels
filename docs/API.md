# FastChannels API

FastChannels scrapes free streaming services and publishes them as M3U playlists and
XMLTV guide data for Channels DVR, Plex, and generic IPTV clients. Everything the
admin UI does, it does over the HTTP API described here.

The machine-readable reference is [`openapi.yaml`](./openapi.yaml) — 182 paths, 191
operations, generated by reading every route handler in `app/routes/` at version
5.0.4 and verified to match the code exactly. This document is the orientation guide:
what the surfaces are, how to use them, and what to watch out for.

> **This is not an upstream-published contract.** FastChannels ships no API docs and
> no OpenAPI document. This describes observed behaviour of a private backend that
> the admin UI happens to talk to. There is no versioning and no deprecation policy;
> response shapes can change on any release. Pin your container tag if you build
> against it.

---

## Read this first: there is no authentication

Not a single route checks a credential. `create_app()` registers one `before_request`
hook and it only assigns a request ID (`app/__init__.py:36`). There is no login, no
session, no API key, no bearer token, nothing.

Anything that can open a TCP connection to the port can:

- read and overwrite provider passwords — `POST /api/settings/tve/cox`
- download the entire database, credentials included — `GET /api/settings/backup-db`
- **replace** the database — `POST /api/settings/restore-db`
- tail the application log — `GET /api/logs`
- start interactive browser logins that spend real credentials
- point the server's headless browser at an arbitrary URL — `POST /api/custom-channels/detect`

Two endpoints perform server-side fetches with no host or private-address filtering:
`POST /api/custom-channels/detect` (and its `/start` variant) and
`GET /images/proxy/{type}/image.{ext}`. From inside a container these reach your LAN
and the container's own loopback services.

**Bind the port to loopback** (`127.0.0.1:5523:5523`) or put the service behind a
reverse proxy that enforces authentication. Do not expose it to a network you do not
control.

## Quick start

```bash
BASE=http://127.0.0.1:5523

# What's running
curl -s $BASE/api/system-stats | jq '{uptime_seconds, db: .db.channels_active}'

# What sources exist
curl -s $BASE/api/sources | jq -r '.[] | select(.is_enabled) | "\(.name)\t\(.channel_count)"'

# Find a channel
curl -s "$BASE/api/channels?source=roku&search=ABC7&per_page=5" | jq -r '.channels[] | "\(.id)\t\(.name)\t\(.stream_url)"'

# Play it — 302s to the real CDN URL
curl -s -o /dev/null -w '%{http_code} -> %{redirect_url}\n' \
  "$BASE/play/roku/f99ba08f0a86593eb59a754e57720d85.m3u8"

# The playlist and guide a DVR would consume
curl -s $BASE/m3u | head -5
curl -s $BASE/epg.xml | head -3
```

## The five surfaces

| Prefix | What it is | Who calls it |
| --- | --- | --- |
| `/m3u`, `/epg.xml`, `/feeds/{slug}/…` | Playlist and guide outputs | Channels DVR, Plex, IPTV clients |
| `/play/…`, `/watch/…` | Stream resolution, manifest/segment proxies, DRM license proxy | Media players, the browser watch page, PrismCast |
| `/logos/…`, `/posters/…`, `/images/proxy/…` | Cached image proxy | Whatever renders the guide |
| `/api/…`, `/api/feeds/…` | Control API | The admin UI — and you |
| `/admin/…` | Server-rendered HTML pages | Browsers only — **not** an API |

### Outputs — the part you actually subscribe to

Four playlist flavours, each pairing with a guide:

| Playlist | Guide | Use when |
| --- | --- | --- |
| `/m3u` | `/epg.xml` | Normal case. Guide data comes from FastChannels. |
| `/m3u/gracenote` | *(none — DVR fetches its own)* | Channels DVR with a Gracenote subscription. Emits `tvc-guide-stationid`. |
| `/m3u/prismcast` | `/epg.xml` | DRM channels bridged through a PrismCast server. |
| `/m3u/prismcast/gracenote` | *(none)* | Both of the above. |

Gracenote and XMLTV guide data **cannot be mixed within one DVR source**, which is why
they are separate playlists rather than one with a flag. Register both if you have a
mix of channels.

Every flavour exists per-feed too: `/feeds/{slug}/m3u`, `/feeds/{slug}/epg.xml`, and so
on. A *feed* is a saved filter — a named subset of the lineup with its own channel
numbering. Create them with `POST /api/feeds`.

Unfiltered output requests serve a pre-built artifact. Adding any of `?source=`,
`?category=`, `?language=`, or `?search=` switches to live generation, which is
correct but slower — don't put a filtered URL in a DVR that re-polls every hour.

### Playback

`/play/{source}/{channel_id}.m3u8` is the URL that appears in generated playlists. It
resolves the channel through its scraper — refreshing tokens, re-detecting expiring
URLs, consulting caches — and **302-redirects** to the upstream CDN. Some sources
return a proxied manifest instead, because their CDN rejects requests that do not come
from the server (IP-bound tokens, `Referer` gates, CORS locks).

`/watch/{id}` is an HTML player page. It exists so PrismCast's headless Chrome can load
a DRM channel, decrypt it in the browser CDM, and re-stream the result — that is the
whole DRM-bridge mechanism.

### Control API

`/api/…` is the admin UI's backend: sources, channels, feeds, Gracenote mapping,
settings, and diagnostics. Roughly 130 operations. See the index below.

## Conventions

**Content types.** JSON in, JSON out, except: outputs return `application/x-mpegurl`
and `application/xml`; playback proxies return manifests and media bytes; the license
proxy takes and returns raw binary; `POST /api/settings/restore-db` takes
`multipart/form-data`.

**Errors.** Most `/api` routes return `{"error": "message"}`. A few — the Gracenote
contribution and remote-map endpoints, the DVR pushes, the TVE tests — use
`{"ok": false, "message": "…"}` instead. Unmatched routes return Flask's **HTML** 404
page, not JSON, so do not assume a JSON body on error.

**Two retryable states, both `503`:**

| Response | Meaning | What to do |
| --- | --- | --- |
| `503` + `Retry-After: 15`, body `"… artifact is warming"` | Background worker is still building the playlist or guide | Retry in ~15 s. Normal right after startup or a config change. |
| `503` + `Retry-After: 30`, body `"Stream temporarily unavailable."` | Stream resolution failed — timeout, expired token, or an active back-off after the source rate-limited us | Retry after the delay. **Do not** retry immediately; some sources punish it. |

The second one is deliberately opaque to the client so players back off instead of
blacklisting the channel. The real cause is in `GET /api/logs` — match on the
`X-FastChannels-Request-ID` header returned with the failure.

**Writes that are locked out by scrapes.** SQLite is single-writer. Endpoints that
write during a running scrape can return `503` with
`"Server is busy (a scrape is in progress)"` or `"Database busy"`. Retry.

**Channel-number collisions.** Anything that could make two channels share a number in
some output is rejected with `409` and a `warnings` array, and the change is rolled
back. This applies to source edits, feed creation and edits, and manual reordering.
Only *newly introduced* overlaps block — pre-existing ones are tolerated.

**Request correlation.** Send `X-Request-ID`; it is echoed as
`X-FastChannels-Request-ID` and appears in every log line for that request. On `5xx`
you also get `X-FastChannels-Failure-Stage` (`license`, `watch-page`, `manifest`,
`resolve`, or `server`).

## Common workflows

### Subscribe a DVR without touching its UI

`POST /api/feeds/{id}/push-to-dvr` registers the feed directly in Channels DVR — up to
two sources (Gracenote-guided and standard), with the XMLTV URL attached and a 24-hour
refresh. Feed artifacts are rebuilt synchronously first, so the DVR fetches current
content rather than a stale file.

Over 750 channels returns `409` with `requires_confirm: true`; re-send with
`{"force": true}` to proceed. Equivalents exist for a single source
(`/api/sources/{id}/push-to-dvr`) and the whole lineup (`/api/raw-output/push-to-dvr`).

Check connectivity first with `GET /api/dvr/test-connection`.

### Add a custom channel from a web page

```bash
# 1. Kick off detection (async — page URLs drive yt-dlp or a headless browser)
ID=$(curl -s -X POST $BASE/api/custom-channels/detect/start \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/live"}' | jq -r .detect_id)

# 2. Poll
curl -s $BASE/api/custom-channels/detect/$ID | jq '{status, stage_text, stream_url, headers}'

# 3. Create the channel from the result
curl -s -X POST $BASE/api/custom-channels -H 'Content-Type: application/json' -d '{
  "name": "Example Live",
  "stream_url": "<stream_url from step 2>",
  "custom_headers": { },
  "proxy_segments": true,
  "redetect_on_play": true,
  "page_url": "https://example.com/live"
}'
```

Carry the detected `headers` into `custom_headers` and set `proxy_segments: true` — the
server then applies them to segment fetches, which a client cannot do on a bare
redirect. Set `redetect_on_play: true` for sources whose URLs expire, so each play
re-resolves from `page_url` rather than serving a dead CDN link.

### Bulk channel edits

`POST /api/channels/bulk` and `POST /api/channels/gracenote-bulk` take the same filter
vocabulary as the admin channel list — see `ChannelFilters` in the spec for all 18
dimensions. Both run as background jobs and return the matched count immediately:

```bash
# Disable every dead channel from one source
curl -s -X POST $BASE/api/channels/bulk -H 'Content-Type: application/json' \
  -d '{"action":"disable","filters":{"source":"roku","drm":"dead"}}'
```

For Gracenote, `set_off` keeps the stored ID dormant so it survives re-enabling;
`clear_ids` is the only action that destroys it.

### Diagnose a channel that will not play

```bash
# What does the server think the stream is?
curl -s -X POST $BASE/api/channels/1314/inspect | jq
```

Always returns `200`; the verdict is in `status`:

| Status | Meaning |
| --- | --- |
| `live` | Manifest parsed and a segment returned bytes |
| `bridge` | DRM, but the DASH+Widevine path and license are present — plays via PrismCast |
| `drm` | Encrypted with no usable bridge |
| `dead` | Upstream 404/410 |
| `vod` | Finished recording, not a live channel |
| `no_data` | Manifest fine, segments empty or erroring |
| `error` | Everything else — read `detail` |

Inspection also refreshes the channel's stored resolution and codec info as a side
effect. `GET /api/channels/{id}/preview` is the lighter companion: playback URLs,
playback mode, now/next programming, and EPG depth.

### Clean up duplicates

`GET /api/channels/duplicate-summary` reports the scale and the reviewable soft-match
groups. `POST /api/channels/resolve-duplicates` keeps one winner per group, ranked by:
healthy over unhealthy → has a Gracenote ID → better EPG quality → your
`source_priority` order. Groups where every channel is unhealthy get all of them
disabled.

`strict` mode acts on exact canonical-name matches. `soft` mode only touches the
`group_keys` you pass, because brand-word normalisation ("TV", "Channel", "Network")
produces false positives worth eyeballing first.

## Operational notes

**Two endpoints contact third parties.** `POST /api/gracenote/submit-contributions`
sends your channel mappings — app version, source name, source channel ID, Gracenote ID,
channel name, category — to a webhook that defaults to a Make.com endpoint owned by the
upstream project. It is user-initiated and rate-limited to once per 24 hours, but it is
unauthenticated, so anything on the network can trigger it.
`POST /api/gracenote/remote-map/refresh` downloads a GitHub gist owned by the same
project; that same fetch **also runs automatically on every worker start**. It is
parsed as CSV data, never executed.

**Credentials are stored in plaintext.** Provider passwords, tokens, cookies, and saved
browser sessions live unencrypted in `/data/fastchannels.db` and its nightly backups.
Secret config fields are masked as `••••••••` on read and sending that literal value
back means "unchanged" — but `GET /api/settings/tve/cox` returns the **username** in the
clear, and `GET /api/settings/backup-db` hands over the whole database.

**Changing credentials purges cached auth.** Saving a source config where any credential
field changed clears the stored tokens, cookies, and browser session, so the next run
performs a fresh login. This is deliberate: otherwise a stale token keeps authenticating
as the old account and the new credentials are never exercised until it finally expires.

**Interactive sign-ins are three-endpoint dances.** Sling and the TVE networks open a
real browser inside the container and stream screenshots to the caller. The pattern is
always `POST …/start` → poll `GET …/state` (returns a base64 PNG) → `POST …/input`
(clicks and keystrokes) → `POST …/stop`. A human has to solve the captcha; there is no
way to automate past it.

The TVE "sign in to all" cascade is currently rejected server-side with a `400` — the
shared browser page was dying mid-sweep and silently skipping networks while still
reporting success.

**Rate limits are upstream, not local.** The API itself is unthrottled, but the services
behind it are not. Roku in particular returns `403` under Cloudflare rate-limiting and
FastChannels then applies a **source-wide 5-minute cooldown** — every Roku channel
returns `503` until it expires. Retrying makes it worse. This is most likely right after
startup, when all enabled sources scrape at once.

**Pagination.** `GET /api/channels` defaults to 50 per page. Pass `slim=1` for a reduced
field set when you only need names and IDs — noticeably faster on large lineups.
